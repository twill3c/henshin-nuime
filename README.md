# 変身の縫い目(henshin-nuime)

カフカ『変身』を独語原文・英訳・日本語訳の三面で並べ、**どの文がどの文に対応するか
(縫い目)を教師なしで引かせ、その縫い目を測る**解剖台。深層学習の実装訓練を兼ねる。

設計と品質ゲートは [SPEC.md](SPEC.md)、検査は [TEST_SPEC.md](TEST_SPEC.md) を見ること。

## いま何ができているか

L12 まで。三版の取り込みと権利台帳、段落と文への分割、**四つの手法で引いた縫い目**
(長さモデル / 位置だけの対角線 / 多言語埋め込み / 自作 Transformer の cross-attention)、
手法間の差を測る置換検定、**目玉の判定**、正解ラベルを使わない三角整合、
そして公開面の画面五枚(三面の本文 / 縫い目の地図 / 注意の帯 / 一語の変身 / 自分の文を縫う)まで。
最後の一枚は**ブラウザの中で**推論する —— 同じ ONNX を三つ目のランタイムで回し、
局所の値と突き合わせてある(G-18)。あわせて独語原文からの自前和訳を進めている
(**第二章まで 59/97 段落・32,159 字**)。落丁検査 四本と訳語登録簿 25 語つきで、
原田訳は見ないで作っている。

**目玉は落ちた。** 一冊だけで学習した cross-attention は、段落境界を対角線より
上手に守るとは言えなかった(差 +0.0417 / p = 0.105)。詳細は下の「L6 で分かったこと」。

### モデルの入手(約 1.06 GB・git に入れていない)

埋め込みには `paraphrase-multilingual-MiniLM-L12-v2` を使う。**同じ重みを二つの形式で**
落とす —— 一方は onnxruntime に、もう一方は自前の NumPy 順伝播に食わせ、
突き合わせる(G-04)。

```bash
mkdir -p models/paraphrase-multilingual-MiniLM-L12-v2
cd models/paraphrase-multilingual-MiniLM-L12-v2
H=https://huggingface.co
X=$H/Xenova/paraphrase-multilingual-MiniLM-L12-v2/resolve/main
S=$H/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2/resolve/main
curl -sSL -o tokenizer.json  $X/tokenizer.json
curl -sSL -o config.json     $X/config.json
curl -sSL -o model.onnx      $X/onnx/model.onnx          # 470 MB(経路A)
curl -sSL -o model.safetensors $S/model.safetensors      # 470 MB(経路B)
curl -sSL -o model_quantized.onnx $X/onnx/model_quantized.onnx  # 118 MB(経路C の照合用)
```

**量子化版は公開面が実際に落とすファイルである。** ブラウザは Hugging Face から
直接これを取りに行くので、ここに置くのは**局所で同じものを回して突き合わせる**
(G-18)ためだけ。fp32 と比べるのではなく、**同じファイルどうし**を比べる。

モデルが手元に無いと、二実装照合の検査は skip される(理由つき)。他の検査は通る。

`python pipeline/ingest.py` のようなスクリプトパス起動も通る(T-015 が両方を確かめる)。

### `access violation` が出るが、クラッシュではない(HC-192)

`pytest` を走らせると **`Windows fatal exception: access violation`** が毎回 3 件、
`pipeline/nmt.py` の multi-head attention の行列積を指して出る。**これはクラッシュではない。**

torch の **float64** matmul が投げる一次例外を `faulthandler`(pytest が既定で有効にする)が
拾って印字しているだけで、プロセスは終了コード 0 で完走し、数値も正しい。根拠:

- float32 では出ない。倍精度を使う勾配検査(T-050)と参照照合(T-049)でだけ出る。
- `-p no:faulthandler` を付けると消える。単独プロセスでも `faulthandler.enable()` すると出る。
- 出力はヘッドごとのループで書いた参照計算と一致し、勾配も中心差分と 1e-5 未満で一致する。

**「いつも出るから無視」はしないこと。** 上の三点(完走・独立検算・faulthandler 無効で消える)
のどれかが崩れたら、それは本物である。

## L0 で分かったこと

- **独と英は段落構造が完全に一致する**(97 段落・章別 [30, 29, 38])。二つのファイルは
  互いを参照せずに作られているので、これは学習にも推論にも渡さない非循環オラクルになる。
- **日本語は独より細かい**(165 段落)。会話文が行立てになる日本語組版の習慣による。
  本文行 165 件の行頭は全角空白 92 件・鉤括弧 73 件・その他 0 件。
  よって「段落が一致する」ではなく「日本語の段落は独の段落の**細分**である」という
  弱い述語しか使えない。
- **公有の第二英訳は存在しない。** 構想で第二英訳として数えていた PG #26298 は
  LibriVox の**朗読音声**だった([証拠](data/raw/pg26298_readme.txt))。
  Wikisource が挙げる Lloyd 訳(1937)・Corngold 訳(1996)は権利が存続している。
  訳者差は日本語側(原田訳 対 自前訳)で測り、失われた対照の代わりに
  別作品『審判』での外挿検証を置く。

## L1 で分かったこと

- **文の数は 独 696 / 英 771 / 日 1227。** 日本語は独語の 1.76 倍に割れている。
  段落の細分(165 対 97)と同じ方向で、訳出のたびに一文が複数文になっている。
- **各言語の分割規則が担う仕事は、その言語を単独で数えた現象と一件も違わない。**
  独の例外規則(引用の後続節・ダッシュ挿入句)を外すと 30 文増え、直接数えた現象も 30。
  英の略語規則を外すと 31 文増え、`Mr.` 21 + `Mrs.` 10 = 31。
  日の引用助詞規則を外すと 85 文増え、`」と` 84 + `」など` 1 = 85。
  これは二経路一致で、片方は分割器の挙動、もう片方は本文の数え上げである。
- **日本語は句点を閉じ括弧の前に置かない。** `」` 129 件の直前に `。` は 0 件。
  だから `」` 自体が文末の印になる。この組版を知らずに `。` だけで切ると、
  会話文が丸ごと隣の文にくっつく。
- **英語の `Mr.` / `Mrs.` は 31 件すべて直後が大文字。** 素朴な分割器はここで黙って切る。
- **正規化が日本語の全角空白を潰していた**(L0 の欠陥)。青空文庫は感嘆符・疑問符の後に
  全角アキを置く組版で、実測 28 箇所。1 対 1 の置換なので字数も件数も動かず、
  L0 の検査は全部緑のまま通っていた(HC-174)。いまは置換の差分そのものを検査している。

## L2 で分かったこと

長さだけを手がかりに縫い目を引いた(Gale & Church 1993 の長さモデル)。
アライナには**文の本文しか渡していない** —— 段落も章も識別子も渡していないので、
段落オラクルでの評価は held-out である。

| 組 | 手法 | 段落一致率 | 細分の破れ |
|---|---|---|---|
| 独→英 | 長さモデル | **0.9949** | 3/97 |
| 独→英 | 対角線(対照) | 0.5577 | 64/97 |
| 独→日 | 長さモデル | — | 56/165 |
| 独→日 | 対角線(対照) | — | 57/165 |

- **独↔英は長さだけで縫える。** 文字数以外に何も見ていないのに、段落一致率 0.9949。
  位置だけの対角線は 0.5577 なので、これは対照との差として読める。
- **独↔日では長さは効かない。** 破れが 56 対 57 で、対角線とほぼ区別がつかない。
  表記体系をまたぐと文字数は対応の手がかりにならない。
  **これが L3 で埋め込みを持ち込む理由を、仮定ではなく実測で与えている。**
- パラメータの出所を分けてある。伸縮率 `c` は本文の総字数比だけから出す(対応を使わない)。
  分散 `s²` は Gale & Church の公表値 6.8 を**この corpus に当てはめ直さずに**使う。
  当てはめるには対応が要り、対応こそが測りたいものだからである。

## L3 で分かったこと

**同じ重みを二つの経路で走らせて突き合わせた**(G-04)。経路 A は onnxruntime、
経路 B は**このプロジェクトが NumPy で素から書いた BERT の順伝播**
(safetensors の読み取り・multi-head attention・LayerNorm・厳密 gelu まで自前。
`nn.Transformer` の類は使っていない)。

| 比べたもの | 最大差 |
|---|---|
| 経路A × 経路B(トークン単位・最終層) | 4.768e-06 |
| 同・平均プーリング後 | 4.545e-07(cos 最小 0.99999976) |
| **陽性対照**: 経路B の重みを 1 要素 +0.05 | 9.156e-04 |

比べているのはプール後の 384 次元ではなく**トークンごとの最終層出力**。
平均で打ち消し合う経路の食い違いも見えるようにしてある。

**切り詰めの表を一度測り違えた。** `tokenizer.json` には truncation(128)と padding が
焼かれており、読み込んだだけのトークナイザで長さを測ると**全系列が 128 に揃う**。
そこから「128 を超えたものは 0 件」というもっともらしい嘘が出て、検査は全部緑のまま
manifest に焼かれかけた。測り直した実態は、独 2.2%(トークンの 1.68%)・英 0.9%・日 0.3%。

## L4 で分かったこと — 埋め込みは日本語との縫い目も引く

三手法を**同じ段落オラクル**で測った。アライナに渡るのは本文かベクトルだけで、
段落・章・識別子はどれにも渡らない(G-03)。

| 組 | 手法 | 段落一致率 | 細分の破れ | 被覆(src/dst) |
|---|---|---|---|---|
| 独→英 | 埋め込み | **1.0000** | 0/97 | 0.997/0.970 |
| 独→英 | 長さモデル | 0.9949 | 3/97 | 1.000/1.000 |
| 独→英 | 対角線 | 0.5577 | 64/97 | 1.000/1.000 |
| 独→日 | 埋め込み | — | **1**/158 | 0.996/0.765 |
| 独→日 | 長さモデル | — | 56/165 | 1.000/0.998 |
| 独→日 | 対角線 | — | 57/165 | 1.000/1.000 |

- **独↔英は完全に縫えた。** 754 本の対応が**一本残らず**対応する段落に落ちた。
- **長さが効かなかった独↔日で、埋め込みは効く。** 同じ 158 段落で 56 対 1。
  L2 の結論は「手がかりが無い」ではなく「**文字数という手がかりが無い**」だった。
- **被覆率が違うので、そのまま並べてはいけない。** 埋め込みの手法は偶然の水準を
  超えない対応を組まないため、日本語側で 23.5% の文を飛ばしている。飛ばすほど
  破れは減って見えるので、全手法が覆った共通部分で測り直した — 結論は変わらない。
- **1.0000 は物差しの縮退ではない。** 対の埋め込みを無作為に入れ替えると
  段落一致率は 0.0087〜0.0167 に落ちる。
- **調整できるつまみを置いていない。** 良し悪しの基準は「無関係な組がどれくらい
  似て見えるか」(全対の cos の平均)で、これは対応を使わずに計算できる。

## L5 で分かったこと — 主張を一つ取り下げた

上の表を見て「埋め込みが長さモデルを上回った」と書きたくなる。**検定に通らない。**

対応のある置換検定に掛けた。同じ単位を二つの手法が処理した結果があるので、
帰無仮説は「どちらの手法で処理したかは出来不出来に関係ない」。手法の札を入れ替えて
差の分布を作る。並べ替えの単位は**段落ブロック**にした — 単調な DP は隣の文に
引きずられるので、文ごとに入れ替えると相関を壊して p が甘くなる。

| 組 | 比較 | 差 | p |
|---|---|---|---|
| 独→英 | 一致率 埋め込み − 対角線 | +0.4524 | < 0.0001 |
| 独→英 | 一致率 埋め込み − 長さモデル | +0.0058 | **0.245** |
| 独→英 | 破れ 埋め込み − 長さモデル | +0.0309 | **0.251〜0.255** |
| 独→日 | 破れ 埋め込み − 長さモデル | +0.3481 | < 0.0001 |
| 英→日 | 破れ 埋め込み − 長さモデル | +0.3312 | < 0.0001 |

- **埋め込みが長さモデルに勝つと言えるのは、日本語を含む組だけ。**
  独↔英の 1.0000 対 0.9949 は共通部分 694 文のうち 4 文の違いで、偶然と区別がつかない。
  SPEC に書いていた「長さモデルを上回り」は**この検定の結果を受けて直した**。
- 日本語を含む組はブロック幅を 1 から 10 まで動かしても p < 0.0001 で、
  **並べ替えの単位の取り方に依存しない**。ブロック幅は本文の構造から決まらないので、
  一つに決めず三通りとも出している。
- **検定器そのものを別経路で確かめた。** ブロック数が少ない場合は入れ替えの通り数が
  有限なので全数列挙で厳密な p が出せる。Monte Carlo の値がそれと合うことを
  12 ブロック(4,096 通り)で確認している。統計の道具は壊れていても
  もっともらしい値を返すので、値を見ても正しさは分からない。

## L6 で分かったこと — **目玉は落ちた**

事前に登録した予測は二つの部分からなる。**前半は成立し、後半は落ちた。**

### 前半「翻訳としては使いものにならない」— 成立

自作の Transformer(multi-head attention を素で実装。`nn.MultiheadAttention` も
`nn.Transformer` も使っていない)を『変身』一冊だけで学習した。
30 エポックで損失 5.9421 → 2.4442。出力は英語として流暢だが、内容が原文と無関係である。

| | |
|---|---|
| 独語入力 | `als gregor samsa eines morgens aus unruhigen träumen erwachte , …` |
| 正解英訳 | `one morning , when gregor samsa woke from troubled dreams , …` |
| 生成 | `" what ' s no more than i ' t have to go to go about it . " , and <unk> . samsa , …` |

一冊(独 30,574 トークン)では、**英語の語の並びは覚えても、独語との対応は覚えない**。

### 後半「cross-attention は対角線を上回る」— 落ちた

| 手法 | 対応 | 段落一致率 | 共通 360 文 | 被覆(src/dst) |
|---|---|---|---|---|
| attention | 360 | 0.5694 | 0.5694 | 0.517/0.467 |
| diagonal | 771 | 0.5577 | 0.5379 | 1.000/1.000 |

置換検定(単位 src 文・ブロック 段落・95 ブロック): **差 +0.0417、p = 0.105。**
事前に決めた閾値 p<0.01 に届かない。**主張を差し替える** ——
「一冊だけで学習した cross-attention は、段落境界を対角線より上手に守るとは言えない」。

**予測は消していない。** SPEC §3.6 に書いた予測はそのまま残し、§3.7 に結果を併記した。
主画面は L4 の埋め込み由来の縫い目で成立させる。

### 平均で薄まったのではない

まず疑うべきは「特定のヘッドが対応を担っていて、平均で消えたのでは」である。
層 × ヘッドの 12 通りを個別に測った:

| | ヘッド0 | ヘッド1 | ヘッド2 | ヘッド3 |
|---|---|---|---|---|
| 層0 | 0.5675 | 0.5525 | 0.5601 | 0.5357 |
| 層1 | 0.5337 | 0.5604 | 0.5663 | 0.5435 |
| 層2 | **0.5852** | 0.5549 | 0.5559 | 0.5615 |

対照は 0.5577。**12 通りのどれも対照の近傍に散っている**(0.5337〜0.5852)。
平均が薄めたのではなく、どのヘッドも学んでいない。
なお最良の 0.5852 は 12 回試した最大値なので、成績として読んではならない。

### 学習対の作り方が循環の要だった

対は**位置だけ**で切っている(独語の連続 4 文の窓と、その位置に比例する英語の窓)。
段落・章・識別子・他手法のアラインメントは、入力にも損失にも入らない。
モデルが対応について知りうるのは「だいたいこの辺り」だけで、
それは**対照(対角線)が既に持っている情報**である。だから attention が上回れば
上回ったぶんは本文から来たと言えた —— 上回らなかったので、そうは言えない。

## L7 で分かったこと — 満点を取ったのは、いちばん悪い手法だった

日本語の段落構造は独語と違うので、独→日の縫い目は段落一致率で測れない。
そこで**正解ラベルを使わず、経路の独立性**で検算した:
`de→ja` の縫い目と `(de→en)∘(en→ja)` の合成は、同じ日本語の文を指すか。

| 手法 | 三角整合率 | 帰無 | 段落一致率(独→英) |
|---|---|---|---|
| diagonal | **1.0000** | 0.0020 | 0.5577(最下位) |
| embedding | 0.9696 | 0.0012 | 1.0000 |
| gale_church | 0.2744 | 0.0032 | 0.9949 |

**予測を三つ書いてから測り、三つとも当たった。**

- **予測1 ○ 対角線は 1.0000。** 比例写像の合成は比例写像なので**自明に一致する**。
  そして対角線は、段落一致率でも細分の破れでも三手法中いちばん悪い。
  **満点を取ったのは、いちばん悪い手法だった** —— この物差しは
  必要条件であって十分条件ではない、を実測で示せた形になる。
- **予測2 ○ 埋め込み 0.9696 は対角線を下回る。** 実際の誤りと飛ばしを持つぶん、
  自明に一致する手法には勝てない。
- **予測3 ○ 帰無は 0.0012〜0.0032 に崩れる。** 埋め込みの一致は自明でも偶然でもない。

**想定していなかったこと。** 長さモデルは 0.2744 と低い。§3.2 では独→日の長さモデルは
細分の破れで対角線とほとんど区別がつかなかった(56 対 57)のに、三角整合では大きく違う。
**二つの物差しは別のものを見ている** —— 細分の破れは「日本語の段落をまたいだか」を、
三角整合は「経路によって答えが変わるか」を測る。長さモデルの誤りは
位置的にばらけているのではなく、**経路依存**である。

## L8 で分かったこと — 検査が全部緑のまま、画面は真っ白だった

公開面(Next.js の静的書き出し)を立て、画面「三面の本文」を作った。
独語・英語・日本語の三列を**独語の段落で揃えて**並べ、文をひとつ選ぶと相手が光る。
縫い方(意味の近さ / 文字数だけ / 位置だけ)を切り替えて、縫い目の違いを見比べられる。

このループで踏んだものが、そのままこの企画の教訓になっている。

- **型検査もビルドも 93 件のテストも全部緑のまま、画面には一文も出ていなかった。**
  `fetch("./data/...")` と相対で書いたので、`/yomu/` に置かれた画面からは
  `/yomu/data/...` に解決されて 404 になっていた。実ブラウザで開いて初めて出た。
- **「一手法で測って全手法の話に広げる」を、自分のガードが止めた。**
  章をまたぐ対応は埋め込みで 0 本だったので「どの手法でも 0 本」と書きかけたが、
  実測すると長さモデル 1/48 本・対角線 15/56 本。章ごとに自己完結するファイル構成
  という設計判断が、その誤った前提に乗っていた。
- **スクリーンショットの濃淡を見て「色が付いていない」と読み、DOM を測って裏を
  取ろうとして、今度は測る時刻を間違えた。** 色は 90ms かけて変わるので、
  クリック直後の `getComputedStyle` は変わる前の値を返す。300ms 待てば正しく出る。
  **測定そのものにも射程がある。**
- **単調性の述語を二度、広く書きすぎた。** 2 対 2 の対応は 2×2 の格子状に組を生むので
  「(i,j) 順に並べた j が非減少」は成り立たない。行の組み立てでも
  「どの行にも独語がある」は、章をまたぐ対応を持つ手法では成り立たない。

## L9 で分かったこと — 検査がまず、自分の誤りを捕まえた

図を二枚作った。**「縫い目の地図」**は三手法の経路を同じ軸に重ね、
**段落の切れ目を薄い格子として敷く** —— 答え合わせに使うオラクルを、そのまま
目に見える形にしたものである。経路が升目の中を通っていれば段落を守れている。
**「注意の帯」**は落ちた目玉を落ちたまま図にした。判定(段落一致率 0.5694 対 0.5577、
差 +0.0417、p = 0.10529)を画面の最上部に置いてある。

- **`getBBox()` で図のはみ出しを測ってはいけない。** 返るのは要素自身の座標系、
  つまり**変換を適用する前**の矩形である。`rotate(-90)` を掛けた縦軸ラベルでは
  回転前の位置と `viewBox` を比べることになり、**正しく描かれているものを
  6 件はみ出しと報告した**。画面座標(`getBoundingClientRect`)で比べれば 0 件。
  直す前にスクリーンショットで実物を見たので、正しいものを壊さずに済んだ。
- **目視の印象は当てにならない。** 図で注意の経路が対角線から系統的にずれて見えたので
  数で確かめると、平均 +0.13 文・中央 −0.04・範囲 ±3.9(窓が許す帯幅そのもの)で、
  ずれは無かった。
- 注意の点数表は疎(696×771 のうち 1%)なので**三つ組で焼く** —— 82 KB で済む。
  密に書けば 2 MB を超える。

## L10 で分かったこと — 揃える規則を一つ取り落としていた

画面をもう一枚(**「自分の文を縫う」**)。入力した文を**ブラウザの中で**埋め込み、
三版の本文から最も近い文を引く。課金の生じる推論は無く、サーバ関数も無い。
これが**三本目の経路**である —— 経路A(onnxruntime / Python)、
経路B(自前の NumPy 順伝播)、そして経路C(transformers.js / WASM)。

**照合は同じモデルファイルどうしで行う。** 公開面は量子化版(112.8 MiB)を使うので、
fp32 で焼いた本文とは直接比べられない。実測では fp32 対 量子化で
最大差 8.27e-02・cos 中央 0.995136。**だがその食い違いは検索には効かない** ——
量子化で埋め込んだ照会を fp32 の本文に当てると 120/120 で正解が 1 位に来た。
ずれ(cos 0.99)は別の文との差(偶然の水準 cos 0.26)よりはるかに小さい。

- **量子化モデルは、まとめて通すか一文ずつ通すかで出力が変わる。**
  期待値を 3 文まとめて作り、ブラウザは一文ずつ回すので、2 件が許容を超えて落ちた。
  切り分けの実測(同じ 3 文):**fp32 は最大差 0.000e+00(ビット単位で同一)、
  量子化は最大差 7.538e-02・cos 最小 0.986824**。埋め草を含む入力の形が変われば
  量子化の演算が変わる。dtype・語彙・切り詰め長は揃えていたのに、
  **バッチの組み方**を揃えていなかった。**これも揃える規則である**(HC-073)。
  規則を文章で書くだけにせず、`scripts/make_g18_fixture.py` に置いた ——
  作り直せない期待値は、食い違ったときに何が違うのか切り分けられない。
- **`transferSize` では転送量を測れない。** クロスオリジンの資源は相手が
  `Timing-Allow-Origin` を返さない限り 0 を報告する。Hugging Face は返さないので、
  118 MB 落ちていても 0.0 MB と出る。**測れない値と、値が 0 であることは違う** ——
  最初その 0 を「モデルを読んでいない」と読みかけた。要求の件数と名前で見る。
- **生の float32 で配るデータには構造が入っていない。** `emb-*.bin` は次元がずれても
  文の本数がずれても `Float32Array` に黙って載る。バイト数を数える検査を足した(T-064)。
- 検査は**画面に実際に表示される類似度**を読む。`window.__test` のような隠し口を作ると、
  検品器は利用者が触るものではなく検品器のために用意したものを見ることになる。

## L11 で分かったこと — 素朴な数え方が五つとも壊れていた

独語原文からの自前和訳を始めた。**第一章 30/97 段落・15,866 字。**
原田訳と併記して訳者差を見るためのものなので、**原田訳を見ないで作る**。
器のほうは構造で守れる(`pipeline/translate.py` は日本語版を読む口を持たない)が、
**書く人が読まないことは検査では固定できない** —— そこは手続きの約束だと書き分けた。

落丁検査(原文の何が落ちたかを数える)を組んだところ、思いつく数え方が
ことごとく壊れた。以下はすべて**訳文を一行も書く前に**、原文だけを走査して出たもの。

| 素朴な組み方 | 実測 | 使えない理由 |
|---|---|---|
| 算用数字を突き合わせる | 原文の算用数字 **0 件** | 数はすべて綴りで書かれる |
| 綴りの数を全部数える | `ein`/`eine` が **203 件** | ほとんどが不定冠詞 |
| 語ごとに数を突き合わせる | `halb sieben` | **独語は次の時、日本語はその時を言う** |
| 語幹の前方一致で拾う | `achten` 6 / `zweifel…` 3 | 「注意する」「疑う」であって八・二ではない |
| 大文字を固有名の印にする | 上位が Schwester / Vater / Mutter | **独語は全名詞が大文字** |

- **時刻の言い方は語ごとに訳せない。** `halb sieben` は「七時半」ではなく **六時半**。
  `halb` と `sieben` を別々に数えると、正しい訳文が落ちる。だから照合の単位は語ではなく
  **言い回し**にし、長いものから当てて、当たった範囲を二重に数えないようにした。
- **固有名は英訳から拾える。** 英語は普通名詞を大文字にしないので、文中の大文字が
  固有名の印になる(Gregor 229 / Samsa 34 / Grete 21)。独語側からは拾えない。
- **登録簿に書いた数字も検査の対象にした。** 件数は実測から写したのに初出段落は記憶で書き、
  **13 語中 9 語が実際と食い違った**。もっともらしい数字は検査を素通りする。
  人が書かない約束にせず、原文と突き合わせて落とす形にした。
- **`data/` は字種検査の既定の走査から外れている。** 外部データの原文を置く場所なので
  除外されているが、そこに自前の文章を置くと**無検査のまま出荷される**。
  経路を明示して走らせる検査を自前で持った(陽性対照つき)。
- **三本の検査には穴があった。** 固有名も数も含まない文を一つ落とすと、段落は残り、
  名前も数も揃うので、どれも黙る。原文との字数比を四本目に足した(実測 0.37〜0.48・
  中央値 0.408、帯はそれより広く取る)。段落を半分に切ると、他の三本が黙ったまま、
  これだけが落ちる。
- 検査は五本とも**壊すと落ちること**を確かめてある —— 段落を抜く / 名前を消す /
  時刻を消す / 訳語を揺らす / 段落を半分に切る。「OK」が出ても、
  検査が何も見ていないだけかもしれない。

## L12 で分かったこと — 検査の網の広さは、手で書いた一覧の大きさだった

第二章 29 段落を訳し(通算 **59/97 段落・32,159 字**)、画面**「一語の変身」**を作った。
登録した語ごとに、独語の文と、そこから**縫い目でたどった**英訳・原田訳、
そして自前訳を並べる。「なぜその訳語か」は登録簿に書いた文をそのまま出している。

```
Ungeziefer → 虫けら(1 回・初出 1-1)
  独  … fand er sich in seinem Bett zu einem ungeheueren Ungeziefer verwandelt.
  英  … transformed in his bed into a horrible vermin.
  原田 … 自分がベッドの上で一匹の巨大な毒虫に変ってしまっているのに気づいた。
  自前 … 自分が寝床のなかで、途方もなく大きな一匹の虫けらに変わってしまっているのに気づいた。
```

- **登録簿に無い語は誰も見張らない。** 第二章を訳しているとき、`Reisender` の訳が
  第一章で「外交販売員」2 箇所・「外交員」3 箇所に**揺れたまま出荷されていた**ことに
  気づいた。訳語の一貫性ゲートは登録簿にある語しか見ないので、L11 の検査は
  全部緑のまま揺れを通した。**「検査がある」と「検査が届いている」は別**で、
  後者は被覆でしか言えず、しかも**被覆の穴はゲートの緑として現れる**。
  登録簿を 13 → 25 語に広げ、被覆そのものを数えて出すようにした(59 段落中 51 段落)。
- **語頭の `halb-` は数量ではない。** `Halbschlaf`(まどろみ)を訳したところ、
  数の落丁検査が「halb が無い」と正しい訳文を撃った。是正のとき例外を一つ足さず、
  **本文の `halb` 系 8 例を全部数えてから**決めた —— 単独 5 例は数量なのでそのまま照合し、
  合成語 3 例だけを言い回しの表に置いた。数え切ってあるので、この表は増えない。
  **開いた例外表と、閉じた列挙は別物である。**
- **十代の数は語幹が変わる。** `sechzehn`/`siebzehn` に `sechs`/`sieben` は含まれないので、
  語幹の前方一致では拾えていなかった(各 1 例)。`vierzehn` は拾えている ——
  拾えるものと拾えないものが混ざるので、「前方一致だから十代も見ている」とは言えない。
- **同じ名前を二つの意味に使うと黙って消える。** 焼くとき訳語を `ja` に入れ、
  相手の版の文も `ja` に入れたので、訳語が文の配列に上書きされた。
  焼く側と読む側の両方で、訳語が文字列であることを数えるようにした。
- 検品器のほうも一度誤って撃った。たたむ操作を見るのに**先頭の札**を押していたが、
  一度に開くのは一枚なので、押せば別の札が開くだけで中身は残る。開いている札を押す。
